# 数据更新设计

## 页面与索引的人工更新

发现、团体列表、独立档案、演出与纠错使用 `assets/groups-data.js` 轻量公开索引；原风格图继续使用 `data.js`。`npm run build` 按 `scripts/siteManifest.mjs` 的六个 TypeScript 入口生成普通 IIFE 脚本，并由 `scripts/groupCatalog.mjs` 从既有 data.js 生成399条团体索引。固定输入必须生成固定字节，不以构建日期更新观察时间。不要手改生成的脚本或以候选内容覆盖主档。新页面不依赖运行时 JSON 请求。

新增或调整页面时同步核对公开文件清单；构建缺模块即失败。预览只提供清单及公共图像，打包同样使用该清单，并拒绝缺失文件、非白名单输出和符号链接。`--partial` 只供未完成模块的本地开发，不能代替完整 verify 或发布候选。

纠错相对链接可附 `group`、`event`、`page`、`kind` 单值参数。page 限定 index/discover/groups/group/events/guide/about；kind 为 error/event/outdated/rights。只传本页已经核实的团体或活动 ID；不附任意 URL、自由文本或私人路径。用户须在预填表单中补充说明，主动生成草稿并自行发送。

活动只维护 `data/events.v1.json`，日期、团体 ID、状态和来源按 `docs/EVENTS.md` 核验。城市、整场开演时间、完整阵容或海报依据不足时保持未知，不用出演时段代替整场时刻。`updatedAt` 是实际编辑时间，`observedAt` 是对应来源观察时间；构建不自动刷新这些字段。

修改后执行 `npm ci`（安装固定开发依赖）、`npm run verify`、`npm run preview`。在 375px 和 1440px 检查普通页面与 file:// 离线入口，再执行 `npm run package:site` 生成 `.build/site`。指南、关于、邮件草稿模板同样经本地构建与测试；生成草稿不会上传或发送邮件。

正式数据门不限制活动数量、来源平台或海报必须为空。新增经人工核验的活动、主办方/场地方来源与合法海报无需修改首批测试断言；首批五条的时间及来源特征固定在 `tests/fixtures/events-seed-20260905.json`，只作为历史回归夹具。不要随活动更新改写该夹具。正式门校验结构、主档 ID、来源完整性及素材实体，并拒绝测试保留 ID 和示例来源；真实性仍须人工核验。

有可靠来源与使用依据的本地活动海报放在 `assets/event-posters/`：小写字母/数字开头，文件名主体只含小写字母、数字、下划线或连字符，最多 96 字符；扩展名只允许 `.png`、`.jpg`、`.jpeg`、`.webp`。在 `poster.src` 使用该目录的相对路径，填写 alt 与 sourceUrl。构建、预览和打包共享此合同，只导出正式活动引用的本地文件；缺失、路径越界、任一级符号链接、非普通文件、扩展名与图片签名/基本容器不匹配时明确失败。不从任意 assets 目录收活动海报，不打包未引用文件。安全 HTTP(S) 远程海报保持原规则，不在构建时下载。

移除或改名本地海报后，如果旧 `.build/site` 留有不再引用的文件，打包会拒绝旧输出而不会静默保留。先备份并移走该旧候选目录，再生成新的候选；不要把多次输出直接叠加发布。素材权利不明时继续使用 null，不能用测试图片填充正式资料。

历史 `data.js` 与四份既有公开 JSON 不随活动编辑重写；399 个条目、375 个当前存续标记与严格历史快照分开核对。新增页面没有账号、评论、论坛、招聘、交易、在线投稿接口或调度入口。

回退时使用公开基线 `eb3577403a4aad6b3284f37292bdf353078e6943` 的完整静态站点备份替换候选目录。若已经由站长另行发布，应由站长恢复整套备份，避免混用不同版本 HTML 与脚本。此仓库的构建和打包命令不操作服务器、Git 推送、DNS 或备案。

公开发布前还需独立验收，并由主任务核对站长提供的真实备案号、页面展示及备案范围。不得填造编号。周更任务独立管理，页面候选完成不代表采集与调度已启用。

截至 2026-09-05，自动更新尚未启用。当前站点发布的是经过整理和复核的静态快照，浏览页面不会触发数据采集。后续建议每周更新一次，并继续保留完整团体档案；这份说明记录拟采用的策略，不代表已有可运行的周更任务。

## 自动更新与人工审核

首版拟自动更新已高置信绑定官号 UID 的粉丝数、精确或约数标记、来源和观察时间。身份冲突、字段缺失和异常变化进入复核队列，原有资料继续保留。页面应分别注明粉丝观察日期、存续状态截点和编辑复核日期。

存续状态、解散或复活、成员、风格、地域、官号改绑、头像和展示图继续人工审核。简介和显示名变化先保存为公开观察。请求失败、没有返回或长期没有新博文，都不能据此判定团体解散。

## 拟采用的运行约束

- 缓存优先，同一周期复用已完成的查询；业务响应完整归档并校验，凭据不进入归档或公开文件。
- 每轮设置预算、请求次数和返回条数上限，串行查询并节流。未启用前不安排自动付费查询。
- 登录失效、认证或服务不可用、额度不足、限流、超时或校验失败时停止，保留线上旧版。结果不确定的请求先核实，避免重复扣费。
- 新数据通过校验和所需人工复核后，再构建、发布并检查线上版本；公开仓库只接收审核后的数据与页面资产。

## 启用前仍需完成

现有采集和构建流程主要面向固定日期快照。周期化来源管理、完整失败留存、预算与节流、断点恢复、客观字段应用及发布前检查仍需补齐。完成一次受控运行后，再决定是否启用每周调度。

公开仓库目前没有采集或定时任务入口。运行 `npm test` 只会检查本地页面代码，不会刷新数据。
