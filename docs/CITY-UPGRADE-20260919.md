## 五项实现决定

- 复用 TypeScript strict、esbuild、原生 DOM/CSS、Node 与 SQLite；采用原生浏览器存储、标准 iCalendar、静态预生成，不迁移框架，不新增常驻服务。
- 保留 `data/events.v1.json` 既有严格契约及历史字段。新核验状态宜使用独立版本化补充层，通过稳定 event ID 关联；未知字段不能悄悄放宽，团体身份不能模糊匹配。
- 关注以稳定团体/演出 ID 和现有归一化城市值保存；新页面使用相对链接兼容现有静态托管。订阅需 HTTP(S)，file 模式明确显示下载方式。
- 订阅文件由发布构建生成，访问者请求不触发采集；UID、更新时间、取消状态和修订序号稳定。同一来源缺席不能解释为取消。新更新记录仅源自可证明的变更，不伪造历史动态。
- 发布与审核隔离：后台产生受限、可验证且绑定基线的候选，既有维护发布流程负责验证与应用。本地使用合成密钥和合成数据验证，不复制生产数据库或凭据。

## 数据关系

```text
公开官宣/投稿证据 → 活动核验与编辑候选 → 校验后的公开档案
                              ↑               │
                     私有审核工作台           ├→ 静态页面/城市/我的关注
                                              ├→ ICS 订阅/更新动态
                                              └→ 缩略图/分享与预生成页面
浏览器本地关注 ─────────────────────────────────→ 页面筛选
本地发布模拟 → 原维护及白名单校验 → 本地发行候选 → 本地 HTTP 预览
```

公开页面不能反向写入已发布数据；构建不启动网络采集；新订阅不回写活动。数据流没有互相启动或循环写入。

## 共享接口初始边界

- B 导出关注模型的读取、切换、订阅变化接口；输入类型限 group/city/event，值经主档/城市/活动校验。A 可在活动 UI 预留 `data-follow-type="event"` 与 `data-follow-id`，先通知 B 对接事件委托，避免互写。

- D 的订阅入口 `subscriptions.html`，动态入口 `updates.html`；订阅文件位于专用公开目录并列明生成文件，不允许任意路径通配公开。

- 活动、核验侧层、订阅版本及更新记录需要一致的候选版本与完成标识。旧应用器只原子替换活动主表，F 必须明确新关联层的事务或发布快照边界；A 的旧核验在相关字段变化后不能继续无条件视作当前核验，D 的版本推进失败不能伪造更新成功。

## 风险与降级

| 风险                       | 应对                                                                         |
| -------------------------- | ---------------------------------------------------------------------------- |
| 官宣不可访问或没有所需字段 | 保留未知和原观察时间，记录逐条缺口；完成组件与验证，不编造资料               |
| 数量或访问增长             | 静态生成、分页、按页数据、图片尺寸变体；记录真实体积和实测，不推算并发人数   |
| 存储禁用/损坏或离线        | 浏览继续，提示关注暂存；订阅回退手动下载，更新失败不展示虚构内容             |
| 新版回退                   | 保留旧 URL、数据兼容和发行清单；数据库变更可恢复，候选不自动覆盖公开版本     |
| 平台订阅支持差异           | 说明刷新由客户端决定，取消状态和去重需实测；不给即时到达承诺                 |
| 后台审核和公开内容串扰     | 权限、加密、基线绑定、证据白名单和发布流程分离；合成环境先完成真实 HTTP 验收 |

## 验收与完成标准

- 正常：团体/城市/演出关注、跨页及刷新持久化，城市筛选、近期和周末、事件详情和导航，订阅生成及更新页，投稿→结构化候选→差异预览→审核→本地发布模拟→回读。

- 边界：零结果、仅历史活动、取消/延期/未确认、UTC+8跨日/跨年/周末、未知时间、重复 ICS 导入及稳定 UID、非ASCII文本折行、跨页返回和深链、收藏上限/迁移/无痕环境。
- 保留原 `npm run verify` 和 `npm run verify:console`；运行公开及后台封包，验证两级发布白名单与物化不丢新页面/订阅/缩略图，不放入私有资料。
- 真实浏览器 1440px 与 375px：主路径、键盘、可见焦点、减少动画、加载/空/错误状态。核心页面检查无意外水平溢出，截图实际打开复核。
- 性能报告分别列原始体积、压缩体积、实际页面请求；相同条件对比，不把构建成功或简单文件大小当加载速度实测。
- 在本机启动仅绑定 127.0.0.1 的预览与合成后台供用户查看；记录地址、服务进程和停止方式。未上线必须明确。所有有意义失败修复后复测；不得降低或删除原验收标准。
- 收敛后独立审查最终差异和候选，确认各任务文件归属、测试结果及资料缺口。本地六项范围完成后汇总交付；服务器部署明确不属于当前执行范围。
