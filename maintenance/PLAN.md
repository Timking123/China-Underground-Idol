# 服务器自动维护实施计划

本次把现有活动日更、资料周更和发布验证迁到网站服务器，不依赖 Codex 在线、会话或定时任务。用户已授权实施；无法自动解决的问题通过 Server 酱通知。

## 方案选择

1. **systemd timer + oneshot 服务（采用）**：复用服务器现有 systemd，支持持久化补跑、超时、资源限制、日志与服务失败状态。无需另建常驻 Web 服务。
2. cron + 脚本（最小方案）：安装少，但互斥、超时、错过运行、状态检查都需另写；不采用。
3. 容器调度：便于封装浏览器，当前单服务器会增加镜像与卷维护负担；暂不采用。

## 范围与五项决策

- 新增 `maintenance/` 下的调度入口、浏览器采集、确定性活动变更策略、通知、发布与安装工具；移植已验收的私有数据管线源码及其测试。公开站点仍由现有构建白名单打包。
- 上海时间每日 00:00 活动更新、每周五 00:00 资料更新；同一服务器串行执行，重复周期读取既有回执。错过时间可补跑，失败不自动重发费用不明的请求。
- 日更付费预算为 0；周更每批最多 50、最多 8 批、批间至少 2 秒、保留 4,000 Credit。价格、账号和余额必须取当次有效证据，未知则停止相应收费动作。
- 只自动应用可验证的既有活动时间修订，以及既有身份映射允许的粉丝数。新增身份、阵容、日期、取消与延期等进入待复核队列；缺席不等于取消。采集失败不刷新观察日期。
- 凭据、原始响应、历史计费账与回执保存在公开目录外；通知只含固定错误分类和处理入口，不含源正文或凭据。代码入 Git，运行态不入 Git。

```text
systemd timer -> 串行维护入口 -> 免费公开采集 -> 证据与变更策略
                           -> 周更费用门 -> 官方 CLI -> 私有账本
证据与变更策略 / 周更候选 -> 维护源 -> 构建/测试/浏览器 -> Git -> 原子发布
维护入口 / 发布失败 -------------------------------------> Server 酱
```

数据流不反向驱动调度，没有自动重试收费的环。采集、候选、应用、发布分别留回执；已有 Codex 定时任务暂停，服务器验收后退出旧调度。

## 外部依赖与停止条件

服务器需要 Node 22、固定版本 Playwright 与 Chromium、官方微博 CLI，以及该服务器自己的有效授权。公开微博可能要求正常登录，官方 CLI 授权与价格页面登录分别验证；当前已知价格请求曾返回 401，不能把旧证据换时间冒充新价格。登录缺失只阻塞相关源/周更，不影响其他免费源和通知。

外部页面结构变化、完整正文缺失、账本存在未决请求、身份不匹配、余额/价格未知、公开源与 Git 漂移、构建或浏览器失败、Nginx 配置变化都停止受影响写入，并保存原因。不会推测、绕过验证或付费兜底。

## 验收与回滚

正常路径覆盖定时器日历、已完成周期复用、免费采集、字段白名单应用、构建和候选页面浏览器、Git 与线上清单一致、通知真实回执。错误和边界覆盖锁冲突、网络/登录失败、旧或部分证据、正文与链接变化、未知计费、余额门、通知失败去重、发布 hash 漂移和 HTTPS 验证失败。

发布前生成冻结计划与清单，保留上一个 release；HTTPS 或浏览器失败时按冻结计划回切，记录回滚结果。停止维护可禁用 timer，不删除历史账本、不回滚其他人的 Git、不改写 Nginx 配置。

## 风险检查

- 依赖：外部登录或页面改版会降低覆盖率，进入具名通知并保留旧数据；测试不能代替真实服务器登录验收。
- 故障：服务超时、进程被杀或网络结果未知时不盲目重发；日志与持久化尝试先于外部写入。
- 规模：当前资料范围每轮重算，超过 400 账号或预算门即停止并通知；来源扩展需明确注册与验证模板。
- 前提失效：仓库/线上基线不一致或旧写入者恢复运行时暂停发布；由人工核对归属后再继续。
