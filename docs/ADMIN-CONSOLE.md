# 网站管理后台实施约定

## 本次范围

新增一个沿用 Node.js 22.14 的独立管理服务，改动超过 8 个文件。包括网页投稿、意见与建议，管理员登录与审核，访问趋势、省级热力地图、完整 IP 与访问页面记录、内容巡检、接收设置和操作审计。保持现有静态网站与服务器资料维护任务的独立运行。内容巡检连接公开档案，修订诉求进入审核箱；资料发布继续由既有核验及发布流程执行，后台不启动收费采集或直接覆写自动更新目录。

用户确认：完整 IP 在后台直接显示，明细保存 90 天；私人资料只对管理员开放，保存前加密。

## 方案选择

1. **采用现有运行时的原生能力（选用）**：Node.js HTTP、crypto、SQLite，复用 TypeScript / esbuild / 原生 CSS 与已有省级底图；增加一个管理服务，部署与加密边界清楚，无新数据库服务器。
2. 最小方案：仅新增邮件转发式表单和 Nginx 日志报表。实施少，但不能形成私有审核工作流，也不满足统一加密存储及管理界面要求。
3. 完整 CMS 与独立统计平台：内容权限成熟，但增加服务、升级和迁移成本，对现有小型服务器及静态发布链改动更大。

## 数据流

```text
访客浏览器 ── 静态页面 ── Nginx
    │                       │
    └── 投稿 / 访问事件 ────┤
                            ▼
管理员浏览器 ── 登录 ── Node.js 管理 API ── 加密 SQLite
                            │                  ▲
                            ├── 本地 IP 地区库  │
                            └── 独立密钥文件 ───┘
现有资料维护任务 ── 原发布流程 ── 静态公开资料（后台只读）
```

不形成互相启动或循环写入。访客 IP 从固定反向代理覆盖的头读取，客户端自报的 IP、地区与时间不予采信。

## 五项关键决定

- 采用 AES-256-GCM 对私人记录逐条认证加密，随机 nonce，记录类型和 ID 绑定附加认证数据。投稿内容、联系方式、IP 明细、后台设置、审计及统计载荷均加密。数据库仅保留必要的时间、类别和不可逆检索标签。主密钥独立于数据库、仓库和公开目录；错误密钥或密文损坏直接报错，不回退明文。
- 只有单一管理员账户；密码用 scrypt 加盐散列。会话使用随机令牌、HttpOnly / Secure / SameSite=Strict Cookie，空闲 30 分钟或最长 8 小时后失效；写操作校验 Origin 与 CSRF。无默认密码、公开注册或 URL 登录令牌。
- 访问明细按服务端时间保留 90 天；过期明细与对应去重标签定期清理。每日及地区汇总不含原始 IP，长期保留。上线前没有采集的日期显示没有数据，不生成历史流量。
- PV 为可见网页加载，UV 为同日 IP 与浏览器类型推算的访客数，独立 IP 单列；均不宣称等于真实人数。过滤明显爬虫、后台、健康检查与资产请求，尊重 DNT。页面地址剔除查询与片段，来源仅保留域名，避免收集敏感 URL 内容。
- 地区使用 ip2region 官方离线 IPv4 / IPv6 数据库，不向第三方发送访客 IP。省级地图复用网站底图，以访问量越高越亮呈现；海外和无法定位的记录明确单列，省市不是精确位置。

## 外部依赖和运维

沿用当前 Node.js、Nginx、systemd；新增官方 `ip2region.js` 查询库及本地 xdb 数据文件，无付费 API、第三方账号或发送通知权限。密钥与管理员密码在目标环境初始化；不能提交到 Git，不能从页面源码读取。默认只监听 127.0.0.1，生产入口由 HTTPS 反向代理提供。公开目录和管理服务发行物分开打包。

生产上线需完成独立服务账户、凭据文件、数据目录、Nginx 路由及现有两级静态发布白名单的具体部署核对。先完成本地实现、测试和可审阅候选，再按现有授权范围处理上线；不把本地验证声称为上线成功。

## 风险与应对

| 情形                    | 处理                                                                                        |
| ----------------------- | ------------------------------------------------------------------------------------------- |
| 管理服务或 IP 库不可用  | 静态浏览继续；表单说明失败并保留输入，可使用邮件入口；无法定位显示未知                      |
| 访问增长或恶意提交      | 请求体上限、全局及 IP 限流、分页和索引；达到限额返回明确错误，避免无限队列                  |
| 需要回滚                | 撤回 Nginx API 路由并停止服务，恢复上一静态 release；保留加密数据库与密钥，回滚不删业务数据 |
| IP 无法代表真实人或位置 | 标注估算口径、未知和海外，不推断住址；不添加浏览器定位或设备指纹                            |
| 数据库或备份文件被复制  | 私人载荷仍为认证密文；密钥不得与备份同存，旧明细不能通过备份长期保留                        |
| 主机或管理员会话被攻破  | 加密不能替代运行时权限；限制进程权限、HTTPS、会话过期和审计，禁止公开私有文件               |

## 验收路径

- 正常：提交各类反馈并获得编号；管理员登录、分页查看、按状态筛选、记录处理意见；浏览事件进入每日 PV / UV / IP 和地区汇总；退出后数据不可读。
- 错误：错误密码、匿名 API、跨站写请求、伪造代理头、超大请求、非法类型与 URL、限流、损坏密文或错误密钥、数据库不可写、服务不可达。
- 边界：重复请求幂等、IPv4 / IPv6、零访问、未知地区、跨日、90 天清理后汇总不丢失、分页末尾、会话过期、筛选竞态、重复提交与表单保留。
- 安全：查阅全部 API 的鉴权路径，验证 SQLite / WAL / 备份中不存在测试 IP、联系方式或投稿明文，公开包不含后台代码、数据库、密钥或测试夹具，输出只采用 textContent / 安全 DOM。
- 界面：1440px 与 375px 真实浏览器检查，键盘、空态、错误态、加载态、地图与表格可读性和减少动画。
- 回归：现有 `npm run verify`、后台类型检查和测试、双发布器白名单与物化测试；新增功能不降低原验收要求。

## 视觉与交互

视觉：暗色现场档案工作台，近黑画布、暖灰内容、红色信号，地图和细折线承担视觉焦点。

内容：左侧功能导航，顶部日期与刷新，工作区先展示概况和待处理事项，再进入列表与详情；无营销横幅。

交互：导航和按钮按压缩放 0.96；审核保存后就地反馈；时间范围切换仅内容淡入。尊重减少动画，保留键盘焦点。样式只用原生 CSS，沿用字体与 4/8/12px 圆角。
