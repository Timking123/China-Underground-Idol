# 城市与关注体验设计

视觉论点：沿用黑红现场档案气质，以紧凑字阶、真实资料图和红色状态建立识别。
内容论点：城市选择 → 本地关注 → 已收录近期/周末演出 → 团体与场馆依据 → 指南和纠错。
交互论点：关注按钮 120ms 按压反馈；状态文字原位切换；锚点与浏览器返回保留定位。减少动画时关闭过渡。

## 1. 主题与场景

观众在手机上查找本城现场、在桌面整理关注；用户无需登录。采用现有原生 CSS、DOM 和 TypeScript，不引入新的视觉框架或重做全站。

## 2. 色彩

沿用 app.css：canvas oklch(0.125 0.008 25)、surface-2 oklch(0.19 0.01 25)、text oklch(0.92 0.012 25)、text-soft oklch(0.78 0.014 25)、accent-hot oklch(0.72 0.19 27)。红色只提示选中与重点操作，取消/延期使用明确文字。

## 3. 字体

沿用 Bahnschrift Condensed / Microsoft YaHei UI 标题和思源黑体正文。标题 34/26/20px、600 字重；正文 16px、行高 1.6；辅助文字 14px。大标题字距 -0.022em，日期等宽数字。不下载额外字体。

## 4. 组件与状态

关注是 button，aria-pressed 同步；导航是 a。关注列表使用条目和分隔线，团体图保持真实来源。清空须用户展开二次确认，保留主动城市偏好；失效档案保留 ID 和移除入口。加载、错误、空态不推断无活动。

城市演出在同一区块切换近期与本周末，以 `period=weekend` 保留可分享深链和浏览器返回；避免手机重复浏览同一条日程。缺失时间和场地复用活动核验层，只有原文明确时才显示“尚未公布”。关注页隐私和存储状态集中在页首。

## 5. 布局

最大宽度 1280px，桌面左右 32px、手机 20px。城市演出为主栏、团体/指南为次栏；关注页依城市/团体/演出分区。间距 8/12/20/32/48px，圆角沿用 4/8/12px。

## 6. 层次

黑底与 surface-2 背景层次区分操作区；不用新增玻璃、渐变或重复卡片阴影。档案图与日期形成内容锚点。

## 7. 约束

- ID 仅从正式资料接受新增；不根据名字模糊合并。
- 收藏只保存在浏览器，损坏数据不覆盖，未知版本不迁移。
- 城市场馆只展示有官方/主办/场馆来源的地址记录，注明来自历史活动，不保证当前营业。
- 所有时间筛选采用 UTC+8；取消、延期、待确认不隐藏。
- 不编造成员、作品、历史事件或推荐排序。

## 8. 响应与可访问性

760px 以下变单栏，按钮至少 44px 高；保留换行、无横向溢出。焦点使用现有 focus token，状态以 role=status 读出。1440px/375px 真实浏览器证据放 reports/city-upgrade-b，未执行项明确标注。

## 9. 后续组件提示

城市标题使用 text、34px/600、1.15 行高、-0.022em；条目使用 surface-2、16px 正文、20px 内边距、4px 圆角。关注按钮 44px 高、4px 圆角、选中 accent-hot，按压 scale(.96)、120ms ease-out。所有图像替换必须来自已审核档案和来源链接。
